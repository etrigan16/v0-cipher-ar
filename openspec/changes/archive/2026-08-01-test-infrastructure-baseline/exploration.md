## Current State

### Product reality (what the app actually does today)

- **Landing / marketing site** (Next.js 16.2.4 App Router, React 19, TS 5.7.3 strict, Tailwind 4, shadcn/ui new-york, dark terminal aesthetic): `app/page.tsx` composes Navbar, Hero, Services, Intelligence, AuditExpress, AttackSurface, Phishing, Pricing, Contact, Footer sections. The only live interactivity is the Risk Calculator (`components/risk-calculator.tsx`, client-side scoring) and the Contact form (`components/contact.tsx`), which POSTs to `app/api/send/route.ts` and sends email through **Resend** to a hardcoded Gmail address.
- **Auth** (real, end-to-end): `app/login/page.tsx` + `app/register/page.tsx` + `components/auth-context.tsx` (AuthProvider) call `lib/api.ts` against the FastAPI backend; JWT stored in `localStorage`; `app/dashboard/layout.tsx` guards routes client-side. Backend `backend/app/routes/auth.py` implements register (bcrypt via passlib), login (JWT HS256 via python-jose, 1440 min expiry), and `/auth/me`.
- **Dashboard** (UI shell only, hardcoded zeros): `app/dashboard/page.tsx`, `attack-surface/page.tsx`, `phishing/page.tsx` render stat cards and empty states; no real data is fetched (the ASM/phishing pages do not even call `lib/api.ts`).
- **Backend ASM + Phishing modules are STUBS**: `backend/app/routes/asm.py` (`/asm/assets`, `/asm/scan/{id}`, `/asm/results/{id}`) and `phishing.py` (`/phishing/campaigns`, POST create, results) return placeholder empty/queued responses. No Asset/Campaign/Template/Tenant models exist — only `models/user.py` (Postgres UUID id, email, name, hashed_password, is_active, created_at).
- **Infra**: `docker-compose.yml` runs only `backend` + `caddy` (no postgres/redis/frontend service — backend expects an external DB at localhost:5432; inside compose the `caddy` → `backend:8000` upstream is the only intra-network link). `Caddyfile` proxies aukalabs.com → localhost:3000 and api.aukalabs.com → backend:8000. `next.config.mjs` rewrites `/api/backend/*` → `NEXT_PUBLIC_API_URL` (default localhost:8000) and sets `typescript.ignoreBuildErrors: true`.
- **State**: no `node_modules` installed; no `backend/.env`; `pnpm-lock.yaml` present. Latest commits are branding/landing work; repo has 2 PRs merged, main-only development.

## Approaches

1. **Test infrastructure baseline first (recommended)** — install vitest + RTL frontend, pytest + pytest-asyncio + httpx backend, add minimal but meaningful sample tests (auth flow API tests, utils/auth-context unit tests), fix lint (ESLint 9 flat config), wire `test` scripts, update `openspec/config.yaml` to strict_tdd-ready.
   - Pros: unlocks TDD for every subsequent change; smallest dependency root (everything else benefits); sample tests validate the harness on the two real flows (auth + health).
   - Cons: touches both stacks + lint in one change (needs careful task splitting to stay near 400-line budget); `pnpm install` required first.
   - Effort: Medium

2. **CI pipeline first** — add GitHub Actions before any test runner.
   - Pros: establishes the feedback loop early.
   - Cons: CI has nothing to run (no tests, broken lint, build skips types) — it would be a shell that fails or does nothing meaningful. Wrong order.
   - Effort: Low (but premature)

3. **Docs sync first** — correct README/wiki/ADRs to match the repo before touching code.
   - Pros: removes the "docs drift" confusion for future agents.
   - Cons: does not unblock TDD; wiki is gitignored local context, so value is limited; better as a small follow-up after the baseline change.
   - Effort: Low

## Recommendation

**Approach 1: `test-infrastructure-baseline`** as the first SDD change, in two reviewable slices:

- **Slice A — Frontend**: add `vitest` + `@vitejs/plugin-react` + `@testing-library/react` + `@testing-library/jest-dom` + `jsdom` + `@testing-library/user-event`; `vitest.config.ts` (jsdom, `@/*` alias, setup file); `test` script; sample tests: `lib/utils.ts` (cn/format), `lib/api.ts` (auth calls with mocked fetch), `components/auth-context.tsx` (login/logout/me), `app/login/page.tsx` (form submit happy/error path). Fix lint: add `eslint` (9) + `eslint-config-next` + `eslint.config.mjs`, restore working `lint` script. Remove dead `styles/globals.css`.
- **Slice B — Backend**: add `pytest`, `pytest-asyncio`, `httpx`, `aiosqlite` (dev deps); `backend/tests/` with `conftest.py` overriding `get_db`; tests: `/health`, `/auth/register` (success, duplicate email 400), `/auth/login` (success, bad credentials 401), `/auth/me` (valid/invalid token). Resolve the Postgres-UUID-on-SQLite portability question in design (prefer portable `sqlalchemy.Uuid` + `aiosqlite` for fast local tests; keep postgres integration for CI later).
- **Out of scope (follow-ups)**: GitHub Actions CI (separate change, depends on this one); flipping `typescript.ignoreBuildErrors`; E2E (Playwright); ASM/Phishing real features; docs sync; `SECRET_KEY`/hardcoded-email security hardening.

This is the correct first change because it is the dependency root: `strict_tdd` flips to true only after a working `test_command` exists for both stacks, and every later feature change (real ASM, phishing engine, billing) then runs RED-GREEN-REFACTOR from day one.

## Risks

- **`pnpm install` is a hard prerequisite** — no `node_modules`; nothing runs until install completes. Backend needs a Python env + `pip install`.
- **Next 16 + ESLint 9 flat config compatibility**: `eslint-config-next` must match Next 16; if the pinned version lags, lint setup may need adjustment (fallback: `eslint-plugin-react-hooks` + `@typescript-eslint` manually). Mitigate in apply with a minimal, working config rather than a full ruleset.
- **Postgres UUID model vs. SQLite test DB**: `models/user.py` uses `sqlalchemy.dialects.postgresql.UUID`, which will fail on `aiosqlite`. Design must choose portable `Uuid` type or spin a Postgres test DB (Docker). Portable type is lower friction; keep an integration test path for real Postgres later.
- **Review budget (400 lines)**: sample tests + configs could exceed the budget; tasks phase must forecast and slice (Slice A/B are natural chained PRs). `delivery_strategy=ask-on-risk` will handle it.
- **`typescript.ignoreBuildErrors: true` remains** until CI exists — build can pass with type errors; verify phase must run `tsc --noEmit` explicitly until CI change lands.
- **Security debt** (pre-existing, out of scope): default `SECRET_KEY` in `backend/app/config.py`, hardcoded recipient email in `app/api/send/route.ts`, JWT in localStorage, no rate limiting. Flag to user, do not fix in this change.
