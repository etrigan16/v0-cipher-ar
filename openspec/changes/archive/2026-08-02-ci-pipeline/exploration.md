## Approaches

1. **Single-job workflow (recommended)** — one `quality` job: checkout → pnpm setup → node setup → python setup → install frontend deps → install backend deps → lint → typecheck → FE tests → BE tests → build.
   - Pros: one runner (cheapest), single dependency install, sequential step names give clear failure attribution, ~70 lines of YAML.
   - Cons: no parallelism (irrelevant at 25 tests / ~2-3 min total).
   - Effort: Low

2. **Split jobs** (lint / test / build with `needs`) — parallel jobs.
   - Pros: parallelism, per-job granularity, easier to add a later deploy job as sibling.
   - Cons: dependencies re-installed per job (cache mitigates), ~2-3x more YAML, overkill for this repo size today.
   - Effort: Medium

3. **Add Postgres service container now** — spin postgres:16 in the test job.
   - Pros: future-proof for PG-backed integration tests.
   - Cons: the suite explicitly does NOT need it (SQLite override); adds startup time and flake surface; no PG-backed tests exist. Defer to a dedicated integration job in a follow-up.
   - Effort: Low but premature
